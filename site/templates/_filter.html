{# The catalogue search box. Emitted by the {% block filter %} in base.html, so ONLY the pages that include it get any JavaScript at all — /movies/, /watching/, /shelf/, /quotes/, /games/ and /ideas/. The home page and the blog still ship none. Three deliberate choices: 1. The input is created by the script, not by the markup. A reader with JavaScript off never sees a search field that cannot search. 2. Matching is done against a data-find attribute the template writes, so a film matches on its title, year and genre without anyone having to search the rendered HTML for stray words like "IMDb". 3. Filtering toggles a class instead of removing nodes. Nothing reflows into a different grid, and clearing the box restores the original order exactly — which a remove-and-reinsert approach does not. The Random button lives here rather than in one page's template because it needs exactly what the search needs: the [data-find] items and which of them are currently on screen. It picks from the VISIBLE ones, so it composes with the search rather than ignoring it — type "pixar", press Random, get a Pixar film. Every page that emits this block gets the button; the label comes from data-random on the findable element. #}
