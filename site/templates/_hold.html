{# Lazy images wait until the page has loaded: the hold script, for a page with many lazy images near the top (home, Projects, Games, the films pages). It fills in its `hold` block with this include. Lazy is not late enough on a slow link. Every lazy image within a screen or so of the bottom starts right after layout, while the images on screen are still arriving, and they share the connection: on /projects/ that was about 170 KB of card art, and on the films pages ten posters, so the things you can see arrive later. So while the HTML is parsed, each lazy image has its src and srcset set aside, and they are put back once the page has loaded (which waits for the eager images) and painted, or two seconds after the HTML if something is slow. They are still lazy then, so only the ones near the screen start. "Painted" is the first contentful paint, as the browser reports it once it is on screen, and then two frames more, for the eager images that land just before load. The load event alone is not enough: a preloaded webfont can hold the first paint back past it, and the images then started before anything was on screen. A browser without paint timing goes by load. While it waits, an image with a width and height shows an empty SVG of that size instead, so its box has the shape it will have: an img whose src is taken away is drawn as a broken image, at the broken-image icon's width, and a mark sized by its height alone came out 20px wide instead of 15. _style.css hides it until it is back. A lazy image marked data-wide-eager (ico::pic's wide_eager) is held only on a phone. It is one that is on screen at load on a wide screen and under the fold on a narrow one, like the second and third project cards, so on a wide screen it is left to the browser, which starts it at the first layout. The line is 45rem, the width from which the card art's `sizes` counts two columns. In the head, so the observer is in place before the parser reaches the first image. Put back by attribute, not from a list, so the copies the drift rows make of a held card come back too. Without JavaScript none of this runs. The explanation is here rather than in _hold.js because load_data ships a file's comments with it, and a Tera comment costs nothing. #} {%- import "macros.html" as ico -%} {{ ico::script(path="templates/_hold.js") }}
